# Phase 22 — UI Design Contract

> Visual and interaction contract for the SEO metrics + Yoast-style traffic-light panel that renders inside the Payload admin editor sidebar (Posts and Pages). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note — this is an admin-internal tool, NOT a public marketing surface.** The component is a `type: 'ui'` field at `admin.position: 'sidebar'`. It MUST visually belong to the Payload admin UI, not the public juan-tech.com brand. shadcn (which exists in this repo for the public site) is intentionally NOT used here. The contract is expressed in Payload admin CSS variables and native field markup, matching the existing house style in `src/components/admin/IndexingControl.tsx`, `GSCField.tsx`, `DomainRatingCard.tsx` and `DinoRankWriteButton.tsx`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Payload admin native) |
| Preset | not applicable — admin-internal field |
| Component library | `@payloadcms/ui` primitives (`Button` from `@payloadcms/ui/elements/Button`, `toast`) + native `field-type custom-field` markup |
| Icon library | Inline SVG or unicode glyphs (no new dependency). Admin has no icon set; use simple geometric status glyphs (filled circle / half circle / empty circle) sized 14px |
| Font | Inherited from Payload admin (`--font-body`); never override the typeface |

**Hard rules:**
- Reuse `'use client'` + `useDocumentInfo` / `useFormFields` / `useAllFormFields` hooks (same pattern as the four reference components).
- Wrap the whole panel in `<div className="field-type custom-field" style={{ marginBottom: '2rem' }}>` with a `<label className="field-label">` heading, exactly like `IndexingControl` and `DinoRankWriteButton`.
- Never introduce shadcn, Tailwind classes, or public-site tokens into this component.

## Layout & Anatomy (narrow sidebar)

Target width: a Payload sidebar column, roughly **260–320px**. Design as a single vertical stack — no multi-column layouts, no horizontal scroll. Text wraps; long URLs/keywords use `wordBreak: 'break-word'`.

ASCII wireframe — **scored** state (everything present):

```
┌────────────────────────────────┐
│ SEO · Keyword objetivo          │  ← field-label (14px, 600)
│                                 │
│ ┌────────────────────────────┐ │
│ │  Score          ┌───────┐  │ │  ← score row
│ │  global         │  82   │  │ │     badge = colored pill
│ │                 │ Bueno │  │ │     number 28px + word label
│ │                 └───────┘  │ │
│ └────────────────────────────┘ │
│                                 │
│ Keyword: marketing seo         │  ← 13px, 600 weight on value
│ ┌────────────────────────────┐ │
│ │ Volumen        1.300        │ │  ← metrics grid (label/value rows)
│ │ Dificultad     34           │ │
│ │ Intent         Informational│ │
│ │ Oportunidad    71           │ │
│ └────────────────────────────┘ │
│                                 │
│ Checks (5/7)                    │  ← 11px muted caption + pass count
│ ● Keyword en el título          │  ← green dot + label (13px)
│ ● Keyword en la meta descrip.   │
│ ◐ Densidad en el contenido      │  ← amber half-dot
│   0,4% — apuntá a 0,5–2,5%      │  ← feedback (11px muted, indented)
│ ○ Keyword en subtítulos         │  ← red empty-dot
│   No aparece en ningún H2–H4    │
│ ● Keyword en el H1              │
│ ● Keyword en el slug            │
│ ◐ Keyword en el primer párrafo  │

│                                 │
│ Recalculado hace 1s             │  ← 11px muted timestamp/micro-state
└────────────────────────────────┘
```

**Row spec for the 7 checks:** each check is a two-line block — line 1 = status glyph + check label (single line, may wrap), line 2 = actionable feedback only when state is amber or red (green checks hide the feedback line to reduce clutter). Glyph column is fixed-width (~18px) so labels align.

The seven checks, in fixed order, with bilingual labels:

| # | Check | es label | en label |
|---|-------|----------|----------|
| 1 | keyword in title | Keyword en el título | Keyword in title |
| 2 | keyword in meta description | Keyword en la meta descripción | Keyword in meta description |
| 3 | keyword in H1 | Keyword en el H1 | Keyword in H1 |
| 4 | keyword in slug | Keyword en el slug | Keyword in slug |
| 5 | density in body | Densidad en el contenido | Density in content |
| 6 | first paragraph | Keyword en el primer párrafo | Keyword in first paragraph |
| 7 | subheadings | Keyword en subtítulos | Keyword in subheadings |

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Glyph-to-label gap, feedback line indent step |
| sm | 8px | Gap between check rows, metric rows; helper-text top margin |
| md | 12px | Inner padding of cards (score card, metrics card) |
| lg | 16px | Gap between major sections (score / metrics / checks) |
| xl | 32px (`2rem`) | `marginBottom` of the whole field wrapper |

Exceptions: the field wrapper uses Payload's existing `marginBottom: '2rem'` convention (32px). Card `borderRadius` is 4px (matches `IndexingControl` result box), not a spacing token. No values above 32px — the sidebar is cramped.

## Typography

All sizes inherit the admin typeface; only size/weight are specified.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption (muted: feedback text, check count, timestamp, metric labels) | 11px | 400 | 1.4 |
| Body (check labels, metric values) | 13px | 400 (600 on emphasized values like keyword & metric value) | 1.4 |
| Label (field-label heading, "Score global", section headers) | 14px | 600 | 1.3 |
| Display (the numeric 0–100 score) | 28px | 700 | 1.1 |

Weights used: **400 (regular)** and **600/700 (semibold/bold)** only. No italics except the existing "loading"/placeholder convention (`fontStyle: 'italic', opacity: 0.7`) already used across admin components.

## Color

Color is expressed in Payload admin CSS variables so the panel auto-adapts to admin light/dark themes. Hex values are documented as the light-theme fallback only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--theme-bg)` | Panel background (inherits sidebar) |
| Secondary (30%) | `var(--theme-elevation-50)` | Score card + metrics card surfaces, with `1px solid var(--theme-border-color)` |
| Text — primary | `var(--theme-text)` / `var(--theme-elevation-800)` | Check labels, metric values |
| Text — muted | `var(--theme-elevation-400)` / `--theme-elevation-500` | Captions, feedback, metric labels, timestamp |
| Accent (10%) — status only | traffic-light + badge colors (below) | Reserved exclusively for the 3 status states |
| Destructive | `var(--theme-error-500)` | Same red as the "ausente" traffic state (no separate destructive action exists in this panel) |

**Accent reserved for:** only the traffic-light glyphs/text and the score badge background. Nothing else in the panel is colored — labels, metrics, headings and CTA all stay in neutral admin text/elevation colors. There are no buttons demanding accent here except the standard Payload `Button` for the "no keyword" CTA, which uses native `buttonStyle="secondary"`.

### Traffic-light semantics (green / amber / red)

| State | Meaning | Glyph | Color variable | Light-theme hex | Applies when |
|-------|---------|-------|----------------|-----------------|--------------|
| Green | Óptimo / present and good | ● filled circle | `var(--theme-success-500)` | `#16a34a` | check passes (e.g. keyword in title; density inside target range) |
| Amber | Parcial / present but suboptimal | ◐ half circle | `var(--theme-warning-500)` | `#d97706` | present but weak (density outside target range, keyword appears late in first paragraph) |
| Red | Ausente / missing | ○ empty circle | `var(--theme-error-500)` | `#dc2626` | keyword absent from that location |

> If `--theme-success-*` / `--theme-warning-*` are not exposed in the installed Payload version, fall back to the documented hex values via a local constant. Do not invent new theme variable names.

### Score badge color thresholds

The 0–100 global score maps to one badge color + a word label (color is never the only signal):

| Range | Color (badge bg) | es word | en word |
|-------|------------------|---------|---------|
| 80–100 | green `var(--theme-success-500)` | Bueno | Good |
| 50–79 | amber `var(--theme-warning-500)` | Mejorable | OK |
| 0–49 | red `var(--theme-error-500)` | Malo | Poor |

Badge: rounded pill, white/`--theme-base-0` numeral text on the colored background, 28px number + 11px word beneath. Thresholds match CONTEXT (verde ≥ ~80, ámbar 50–79, rojo < 50); exact score weights are the planner's call and do not change these color cutoffs.

## States

The component renders one of four mutually exclusive states. All states keep the `field-label` heading visible so the panel never collapses to nothing.

### 1. No keyword assigned (`primaryKeyword` empty)
- No metrics, no checks.
- Show CTA empty state: heading + body + native secondary `Button`.
- es: heading "Sin keyword objetivo" / body "Asigná una keyword objetivo en la pestaña Meta para ver métricas y el semáforo SEO." CTA "Asignar keyword".
- The CTA scrolls/focuses the `primaryKeyword` field if feasible; otherwise it is informational text (no broken action). Match `DinoRankWriteButton`'s muted helper-text pattern.

### 2. Keyword assigned, no metrics loaded (METRICS-02)
- Metrics card shows a clear "sin datos" state, NOT zeros: es "Sin datos de métricas para esta keyword." / en "No metrics data for this keyword." in muted caption style.
- The 7 checks STILL run and render (they only need the keyword string). This is the key behavior from CONTEXT.

### 3. Loading / recalculating (debounce micro-state, SCORE-04)
- Triggered while the ~300ms debounce settles or the server analysis request is in flight.
- Do NOT blank the panel or shift layout. Keep the last rendered score/checks and apply a subtle in-place signal:
  - Score badge: keep last value, reduce to `opacity: 0.6`.
  - Bottom micro-text switches to "Recalculando…" (es) / "Recalculating…" (en) in muted caption.
- After resolve, micro-text returns to "Recalculado hace {n}s" / "Updated {n}s ago" (or "Recalculado ahora"). Never use a full-panel spinner — it would make the sidebar flash on every keystroke.
- Initial first-load (no prior result yet) may show italic "Calculando…" placeholder text matching the admin `fontStyle: 'italic', opacity: 0.7` convention.

### 4. Scored (default, data present)
- Full layout per the wireframe: score card + metrics card + 7 check rows + timestamp.
- Check count caption ("Checks (5/7)" / es) summarizes passes (count green as passing; amber and red as not-yet).

### Error state (analysis request fails)
- Do not break the editor. Keep last good render; bottom micro-text shows muted, non-alarming es "No se pudo recalcular. Reintentando…" / en "Couldn't recalculate. Retrying…". Optionally a single `toast.error` on hard failure, consistent with `IndexingControl`. No red full-panel error block.

## Accessibility (color is not the only signal)

Every status communicates through **three** redundant channels, never color alone:

1. **Glyph shape:** ● filled (green) / ◐ half (amber) / ○ empty (red) — distinguishable without color.
2. **Text:** each check always shows its label; amber/red also show the actionable feedback sentence describing the problem and fix.
3. **Score badge:** always shows the numeric value AND a word ("Bueno/Mejorable/Malo"), so the score reads correctly in grayscale.

Additional:
- Add `aria-label` / `title` to each status glyph spelling out the state in the active locale, e.g. `aria-label="Óptimo: keyword en el título"`.
- The score badge has an accessible label, e.g. `aria-label="Score SEO 82 de 100, Bueno"`.
- Contrast: status text that sits on a colored badge uses white/`--theme-base-0`; status glyphs sit on the neutral panel background where the documented hex values clear 3:1 against `--theme-bg`. Do not place amber text on a white background as body copy — keep amber for glyphs/badges only; feedback text stays muted-neutral.
- Respect admin keyboard focus: the only interactive element is the "no keyword" CTA `Button`, which inherits Payload's native focus ring.

## Copywriting Contract

Bilingual `{ es, en }` following the admin locale (same pattern as existing admin fields). es copy in **neutral Spanish, no voceo**.

| Element | es | en |
|---------|----|----|
| Field label | SEO · Keyword objetivo | SEO · Target keyword |
| Primary CTA (no-keyword) | Asignar keyword | Assign keyword |
| Empty state heading (no keyword) | Sin keyword objetivo | No target keyword |
| Empty state body (no keyword) | Asigná una keyword objetivo en la pestaña Meta para ver métricas y el semáforo SEO. | Assign a target keyword in the Meta tab to see metrics and the SEO traffic light. |
| Empty state (keyword, no metrics) | Sin datos de métricas para esta keyword. | No metrics data for this keyword. |
| Recompute — in flight | Recalculando… | Recalculating… |
| Recompute — settled | Recalculado hace {n}s | Updated {n}s ago |
| Error state | No se pudo recalcular. Reintentando… | Couldn't recalculate. Retrying… |
| Score section header | Score global | Overall score |
| Metric labels | Volumen / Dificultad / Intent / Oportunidad | Volume / Difficulty / Intent / Opportunity |
| Checks section header | Checks ({pass}/7) | Checks ({pass}/7) |

**Per-check actionable feedback** (shown on amber/red only). Exact thresholds are the planner's; copy must name the problem AND the fix:

| Check | Red (ausente) — es | Amber (parcial) — es |
|-------|--------------------|----------------------|
| Title | La keyword no está en el título. Agregala, idealmente al inicio. | — (title is pass/fail) |
| Meta description | La keyword no está en la meta descripción. Inclúyela una vez. | — |
| H1 | La keyword no aparece en el H1. Usala en el encabezado principal. | — |
| Slug | La keyword no está en el slug. Ajustá la URL para incluirla. | — |
| Density | La keyword no aparece en el cuerpo. Mencionala en el contenido. | Densidad {x}% — apuntá a 0,5–2,5%. |
| First paragraph | La keyword no está en el primer párrafo. Mencionala al inicio. | Aparece tarde en el primer párrafo. Subila más arriba. |
| Subheadings | La keyword no aparece en ningún subtítulo (H2–H4). Agregala a uno. | Aparece en pocos subtítulos. Reforzá en otro H2–H4. |

(en mirrors the es copy; planner writes the en strings alongside.)
