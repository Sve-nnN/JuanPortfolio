Per-collection data shapes (verified in src/collections):
- Posts: title=`doc.title`, meta=`doc.meta.{title,description}`, slug=`doc.slug`, content (richText) = `doc.content.content`, primaryKeyword = relationship → keyword-metrics (the keyword string is `doc.primaryKeyword.keyword` when fetched at depth>=1)
- Pages: same title/meta/slug; content (blocks) = `doc.content.layout`; primaryKeyword same
- Categories: title=`doc.title`, slug=`doc.slug`, primaryKeyword same; NO body, NO meta field
- Users: name=`doc.name`, primaryKeyword same; NO body, NO meta field (use name as the "title" for the title check; users have no public slug → slug check N/A)

  <name>Task 1: Shared coverage core (auditDoc + runKeywordCoverageAudit)</name>
  <files>src/plugins/seo/utils/keywordCoverageAudit.ts</files>
  <behavior>
    - auditDoc with no keyword → bucket 'noKeyword', no checks run
    - auditDoc (post/page, isListing=false) with keyword failing >=1 check → bucket 'failing', failingChecks lists the red check ids
    - auditDoc (post/page) with all checks green → bucket 'passing'
    - auditDoc (listing=category) → content checks (h1/density/firstParagraph/subheadings) reported as N/A (excluded from failing), only title/slug/meta evaluated
    - auditDoc (listing=user) → title check uses name; slug + meta reported N/A
    - A listing whose only failures are N/A content checks is NOT bucketed as 'failing'
  </behavior>
  <action>
    Create the shared server core. Define types: `CoverageRow` { collection: 'posts'|'pages'|'categories'|'users'; id: string; label: string; url?: string; keyword: string | null; bucket: 'noKeyword'|'failing'|'passing'; score?: number; failingChecks: KeywordCheckId[]; amberChecks: KeywordCheckId[]; naChecks: KeywordCheckId[] } and `KeywordCoverageReport` { generatedAt: string (ISO); counts: { total, noKeyword, failing, passing }; noKeyword: CoverageRow[]; failing: CoverageRow[]; passing: CoverageRow[] }.

    Export `auditDoc(args: { collection, id, label, url?, keyword: string|null, title?, meta?, slug?, content?, isListing: boolean, locale: 'es'|'en' }): CoverageRow` — the PURE, payload-free unit:
    - If keyword is null/empty → return row with bucket 'noKeyword' and empty check arrays. (AUDIT-01)
    - Else call `analyzeKeywordChecks({ keyword, title, meta, slug, content, locale })`. Reuse it — do NOT reimplement any check (key_link).
    - Determine N/A checks: when `isListing` is true, mark the content checks (h1, density, firstParagraph, subheadings) as N/A and drop them from consideration. For users (no slug) also mark slug N/A; for collections without a meta field (categories, users) mark metaDescription N/A. Decide N/A purely from `isListing` + which of title/meta/slug were supplied (undefined source → N/A).
    - From the remaining (non-N/A) checks: red → failingChecks; amber → amberChecks. bucket = 'failing' if failingChecks.length > 0 (any RED among applicable checks — planner discretion: amber is a warning, not a fail), else 'passing'. (AUDIT-02)
    - Carry through `score` from the analyzer result.

    Export `async runKeywordCoverageAudit(payload, opts?: { locale?: 'es'|'en' }): Promise<KeywordCoverageReport>` — the orchestrator:
    - locale defaults to 'es'.
    - Fetch live docs (AUDIT-03 — every call hits the DB, no caching): `payload.find` for posts, pages, categories, users with `depth: 1` (so primaryKeyword resolves to the keyword-metrics doc), `limit: 1000`, `locale`. Use `select` to keep payloads lean where practical.
    - For each doc extract per the interfaces block: keyword = `primaryKeyword?.keyword ?? null` (guard the case where primaryKeyword is still a string id — treat as null keyword since unpopulated); posts content=`content.content`, pages content=`content.layout`, listings content=undefined; isListing = collection is 'categories' or 'users'; users title=name with slug/meta undefined.
    - Build a `url` for each row (best-effort, for the report/UI): posts `/blog/<category>/<slug>` is not required — a `/admin/collections/<collection>/<id>` edit link is sufficient and always correct.
    - Call auditDoc per doc, collect rows, split into the three buckets, set counts and `generatedAt = new Date().toISOString()`.
    - This module is server-only (imports the analyzer which imports `natural`). Add a top-of-file comment stating it must never be imported by client code (the admin view calls the endpoint in plan 23-02, not this module).
  </action>
