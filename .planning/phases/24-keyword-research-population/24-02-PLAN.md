<notes>
- PREREQUISITO operativo (documentar, no implementar): `pnpm sync:keywords` ya upserta keyword-metrics desde content/keywords.md (syncKeywords.ts ~520-523). NO setea primaryKeyword. El operador debe correr `pnpm sync:keywords` antes de `pnpm populate:keywords` para que existan los docs de métricas. El script de este plan debe funcionar igual aunque algún doc falte (crea stub).
- Map: claves = `slug` (locale default es) | `slug.es` | `slug.en`; valor = keyword string. La parte slug es canónica (mismo slug para ambos locales; ej. `astro-vs-nextjs.es` y `astro-vs-nextjs.en`). Ejemplos: `payloadcms-seo.en`, `nextjs-portfolio` (=> es), `headless-cms-comparison.es`.
- Resolución locale desde la clave: termina en `.en` → locale 'en'; termina en `.es` → 'es'; sin sufijo → 'es' (default). El slug es el resto de la clave.
- Resolver slug→doc: buscar primero en colección `posts`, luego en `pages`, por `where:{ slug:{ equals } }`. El slug puede estar localizado: si no hay match con el locale default, reintentá la búsqueda con `locale:'en'`. Reportá slugs sin match (no abortes).
- keyword-metrics NO está localizado; se busca por su campo `keyword` (text). primaryKeyword SÍ está localizado (24-01): el set se hace con `payload.update({..., locale})`.
- KeywordMetrics tiene campo `status` (text). Reusalo para 'needs-research'. NO agregues campos.
- Patrón de scripts del repo: `tsx -r dotenv/config`, `getPayload({config: configPromise})` con `@payload-config`, salida ANSI con helpers green/red/yellow/bold/dim, args por `process.argv`. Espejá src/scripts/audit-keywords.ts y src/scripts/syncKeywords.ts (bloque upsert ~520-523).
- Working tree sucio: el script SOLO escribe en DB (Payload) y, opcionalmente, un reporte markdown en content/. No toca otros archivos de Juan.
- Si la DB no es alcanzable en el entorno headless, el script debe COMPILAR igual; la verificación de tsc/vitest no depende de DB. La corrida en vivo (--dry-run) es best-effort.
</notes>

Traé candidatos con `payload.find({collection:'keyword-metrics', limit:...})` y compará normalizado, o usá where por keyword exacto y, si falla, fallback normalizado en memoria. El match debe ser insensible a mayúsculas y acentos (ej. "Hidratacion Web" ↔ "hidratacion web").

  5. SET: `payload.update({collection, id, data:{primaryKeyword: metricsDocId}, locale})`. Con `--dry-run`, NO escribas: solo registrá qué harías.
  6. Flags: `--dry-run` (no escribe), `--force` (sobreescribe), `--report` (escribe markdown a content/keyword-population-report.md además de consola).
  7. Reporte consola con ANSI: por locale, cuántos seteados / saltados (ya tenían) / sin doc de página / keyword sin métricas. Idempotente: re-correr sin --force no cambia nada.
