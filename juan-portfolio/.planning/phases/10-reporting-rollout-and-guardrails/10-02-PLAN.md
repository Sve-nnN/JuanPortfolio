    ## Overview
    One paragraph: what the linker does (keyword matching + cluster structural links), what it produces (modified .md files + audit report), and when to run it (after adding new posts or after content edits to an existing cluster).

    ## Commands

    Table or code blocks covering:
    ```bash
    # Preview all changes (no files written)
    npx tsx src/scripts/build-internal-links.ts --dry-run

    # Tag unclassified posts with contentRole first
    npx tsx src/scripts/build-internal-links.ts --classify --dry-run
    npx tsx src/scripts/build-internal-links.ts --classify

    # Full apply (ES posts only)
    npx tsx src/scripts/build-internal-links.ts --locale es --yes

    # Full apply (EN posts only)
    npx tsx src/scripts/build-internal-links.ts --locale en --yes

    # Structural cluster links only (skip keyword scan)
    npx tsx src/scripts/build-internal-links.ts --cluster-only --yes

    # Single category
    npx tsx src/scripts/build-internal-links.ts --category tech-seo --yes
    ```

    ## Audit Report

    Explain that every non-dry-run apply writes content/linking-run-YYYY-MM-DD.md automatically.
    Explain each section of the audit file:
    - Summary: total links added, cluster links applied
    - Changed Posts: which files were modified and how many links were added
    - Skipped Matches: why a potential match was not applied (already linked, different category, cross-locale, etc.)
    - Locale Summary: ES vs EN link counts to confirm locale isolation
    - Errors: any write failures

    ## Locale Isolation

    Short note: the linker enforces locale isolation via ContentScanner.isDifferentLocale(). An ES post will never receive a link to an EN post and vice versa. Locale is detected from the idioma frontmatter field (falling back to 'es' when absent). The Locale Summary section of the audit report confirms this per-run.

    ## When to Re-Run

    List the triggers:
    - After publishing a new post: re-run for that post's locale/category
    - After changing a post's primary_keywords or semantic_keywords: re-run with --classify first
    - After adding a new pillar or satellite relationship: re-run with --cluster-only first to wire structural links
    - Monthly full pass: run --locale es then --locale en to catch any new organic keyword matches

    ## Verifying the Run

    ```bash

    pnpm test:int -- tests/int/internal-linking-bulk-locale.int.test.ts

    # Check the audit file was created
    ls content/linking-run-*.md

    # Review the most recent audit
    cat content/linking-run-$(date +%Y-%m-%d).md
    ```
